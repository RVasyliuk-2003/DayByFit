## ✨ Можливості

**Журнал тренувань**

- Календар із тренуваннями на обраний день
- Типи тренувань: зал, бокс, біг та **власні типи** (своя назва й колір, за бажанням із вправами)
- Тренування в залі з вправами й підходами (вага × повторення), підказки назв вправ з історії
- Час доби, тривалість і нотатка для кожного тренування
- **Редагування й видалення** тренувань, **перейменування й видалення** вправ, керування типами тренувань

**Аналітика**

- Прогрес по кожній вправі в часі
- Список усіх вправ із пошуком і останнім найкращим підходом
- Таблиця підсумків з експортом у CSV

**AI-тренер** 🤖

- Чат із тренером, який бачить тренування за останні 12 тижнів, нотатки й прогрес по вправах
- **Відповіді з'являються поступово** (стрімінг), як у справжньому чаті
- **Довготривала пам'ять:** тренер веде короткі нотатки про тебе (цілі, травми, уподобання), оновлює їх у фоні кожні кілька повідомлень, і їх можна стерти
- Пам'ятає розмову, є дія «Очистити чат»
- Денний ліміт повідомлень на користувача, щоб не витратити спільну безкоштовну квоту API
- Кнопка чату, яку можна перетягнути, і вона прилипає до лівого чи правого краю екрана

**Деталі продукту**

- Акаунти з email і паролем; застосунок вимагає входу
- Дані зберігаються в хмарі й приватні для кожного користувача
- Інтерфейс українською й англійською
- Встановлюється як **PWA** (іконка на головному екрані, окреме вікно, кнопка «Встановити» з підказкою для iOS)
- Mobile-first верстка, чат, що враховує екранну клавіатуру на iOS і Android, сторінки з розбиттям коду

## 🏗️ Архітектурні рішення

- **`useSyncedList`**: один універсальний хук для тренувань і типів: завантаження, оптимістичне додавання / оновлення / видалення з **відкатом при збої**, повтор спроби та кеш хмарних даних, прив'язаний до користувача, тому дані не потрапляють між акаунтами.
- **Row Level Security** на кожній таблиці: користувач читає й пише лише свої рядки.
- **Ключ LLM ніколи не потрапляє в браузер.** AI-тренер це Edge Function в Supabase: вона перевіряє JWT користувача, застосовує ліміт, збирає контекст з його даних (через RLS), стрімить відповідь моделі й зберігає розмову.
- **Захист від зловживань:** денний ліміт рахується за повідомленнями, які може записати лише сервер, тож клієнт не може його скинути. Нотатки й текст тренувань передаються моделі як дані, з явною вказівкою ігнорувати інструкції всередині них.
- **Пам'ять** це окрема таблиця, яку функція оновлює у фоні (`waitUntil`), тому підсумовування не гальмує відповіді.
- **Продуктивність:** розбиття коду за маршрутами через `React.lazy`; важкий markdown-рендерер вантажиться лише разом із чатом.

## 🚀 Запуск

**Потрібно:** Node.js 22+, безкоштовний проєкт [Supabase](https://supabase.com), ключ [Groq](https://console.groq.com).

```bash
git clone https://github.com/RVasyliuk-2003/DayByFit.git
cd DayByFit
npm install
```

Створи `.env.local` у корені проєкту:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_KEY=YOUR_PUBLISHABLE_KEY
```

Запусти застосунок:

```bash
npm run dev
```

### База даних

Застосунок використовує такі таблиці, у кожної ввімкнено RLS і є стовпець `user_id` зі значенням за замовчуванням `auth.uid()`:

| Таблиця          | Призначення                                                    |
| ---------------- | -------------------------------------------------------------- |
| `workouts`       | тренування з вправами (JSON), нотаткою, часом доби, тривалістю |
| `workout_types`  | власні типи тренувань                                          |
| `coach_messages` | історія чату з AI (пише лише Edge Function)                    |
| `coach_memory`   | довготривалі нотатки про користувача (пише лише Edge Function) |

Повна схема з політиками Row Level Security: [`supabase/schema.sql`](supabase/schema.sql).

### AI-тренер (Edge Function)

```bash
npx supabase login
npx supabase link --project-ref YOUR_PROJECT_REF
npx supabase secrets set LLM_API_KEY=YOUR_GROQ_KEY
npx supabase functions deploy coach
```

Необов'язкові секрети: `LLM_BASE_URL` і `LLM_MODEL`, щоб перейти на іншого OpenAI-сумісного провайдера чи іншу модель.

## 🤖 Як це створювалось (з допомогою AI)

Цей проєкт створено за допомогою AI-асистента (**Claude**), і я кажу про це відкрито, бо _вміння ефективно працювати з AI є частиною того, що показує цей репозиторій._

**Що робив я**

- Визначав продукт: функції, сценарії користувача, що будувати далі, а що відкласти
- Обирав і спрямовував архітектуру (акаунти, хмарна синхронізація, RLS, Edge Function для тренера)
- Перевіряв кожну зміну, запускав на реальних пристроях і точно описував помилки (клавіатура iOS перекриває поле вводу, білий екран через порядок хуків, вміст під навігаційною панеллю та інші)
- Сам налаштовував і підтримував справжню інфраструктуру: проєкт Supabase, SQL і політики, секрети, деплой на Vercel, роботу з git
- Ухвалював компромісні рішення (наприклад, приховування замість видалення історії чату, заборона видаляти тип тренувань, який використовується)

**Що робив AI**

- Пропонував підходи й компроміси, писав і рефакторив код за моїми вказівками, пояснював помилки та наслідки для безпеки

> Я сприймаю AI як швидкого й обізнаного напарника для парного програмування: він прискорює роботу, але рішення, перевірку, тестування й публікацію беру на себе я.
